# Contributing to Nimesh Builds

Thanks for helping build useful open-source tools. Documentation, design review, reproductions, and thoughtful questions are contributions too.

## Find the right place

- Use [Discussions](https://github.com/orgs/nimeshbuilds/discussions) for questions, early ideas, and examples of a real workflow that needs improvement.
- Open an issue in the affected project's repository for a reproducible bug or a scoped change. Use this community repository for organization docs, branding, and project planning.
- Follow [SECURITY.md](SECURITY.md) for vulnerabilities. Do not report exploitable details in public issues.

This community repository currently contains documentation and templates. ClusterReplica is still in design and validation; please do not assume installation commands or supported versions exist.

## Make a useful proposal

Explain who has the problem, what happens today, what you've tried, and what outcome would help. For Kubernetes examples, include relevant versions and capabilities, but remove credentials, kubeconfigs, internal hostnames, and private data.

For a large change, discuss the approach before implementing it. Small corrections can go straight to a pull request. A maintainer confirming the scope helps avoid overlapping work.

## Send a pull request

1. Fork the relevant repository and create a branch for one focused change.
2. Follow that repository's setup and contribution instructions when available.
3. Explain what changed and why, linking the related issue or discussion.
4. Describe what you actually checked. For docs, preview Markdown and verify links. For code, run the project's documented checks and provide relevant behavioral evidence.
5. Update examples and documentation when the behavior changes.

For this repository, there is no application test suite. Markdown, YAML forms, link targets, and rendered brand assets are the relevant checks.

## Working with AI

AI-assisted contributions are welcome. Review the result, understand it, and verify its behavior before submitting. Mention substantial AI assistance and any limitations that matter to review. Never claim a test ran when it did not, include private input data, or submit content you do not have permission to share.

## Review and conduct

Be patient and respond to feedback with context. Maintainers may ask to narrow a change, request evidence, or decline a proposal that does not fit the project. Follow our [community standards](CODE_OF_CONDUCT.md).
